## Decision (written by hand after the tables, before any holdout or sweep cut existed)

* rbqm.csm and rbqm.qtl_detector: every candidate meets the criteria on these cuts, so the
  defaults stay (z_threshold 3.5, sd_ratio_max 0.6, approach_band 0.02).
* rbqm.kri_monitor: the default breaks the null criterion (mean 1.4 false positives per
  null cut) and no candidate fixes it. Five of the seven null false positives are
  data_entry_lag findings (site medians of 7.4 to 8.4 days against the absolute 7 day
  threshold, which is not a tunable knob in this step), and the strongest deviations
  finding (DC-NULL-S4, site 1004, score 16) is a site whose synthetic deviation rate is a
  genuine outlier draw, more extreme than the planted 4x cluster. The floor with any alpha
  is 1.2. Lowering alpha would remove DC-BASE's single false positive but buys nothing
  on the null criterion and costs sensitivity on data we have not seen, so alpha stays
  at 0.01.
* Nothing in config/default.toml changes. The expected outcome is that the null-cut exit
  criterion fails, and it will be reported as such.
